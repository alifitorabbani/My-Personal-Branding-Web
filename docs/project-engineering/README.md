## Documentation Structure

Each project directory contains:
- `README.md` — Executive summary, tech stack, architecture, API, database, security, contribution, interview prep
- `BUSINESS_REQUIREMENTS.md` — Functional/non-functional requirements, user roles, business rules
- `SYSTEM_ARCHITECTURE.md` — Architecture diagrams, component communication, data flow
- `DATABASE_DESIGN.md` — ERD, table descriptions, constraints
- `API_DOCUMENTATION.md` — All endpoints with auth, requests, responses
- `ALGORITHM_ANALYSIS.md` — (Algorithm-heavy projects) Formulas, complexity, edge cases
- `FEATURE_DOCUMENTATION.md` — Feature-by-feature implementation details
- `TESTING_AND_QUALITY.md` — Test structure, commands, results, coverage gaps
- `SECURITY_AND_PERFORMANCE.md` — Security analysis, performance considerations
- `INTERVIEW_GUIDE.md` — Basic/intermediate/advanced questions with answers (EN + ID)
- `EVIDENCE_INDEX.md` — File paths, line numbers, confidence labels for all claims

## Evidence Standards

All documentation follows these rules:
- **VERIFIED:** Directly confirmed by source code, README, config, or tests
- **DOCUMENTED:** Stated in repository documentation
- **INFERRED:** Reasonable technical conclusion, not directly confirmed
- **UNKNOWN:** Insufficient information
- **RECOMMENDATION:** Proposed improvement, not existing feature

No metrics, achievements, or responsibilities are fabricated. All claims are traceable to repository evidence.
